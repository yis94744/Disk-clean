# 02 - 问题复现文档

按严重程度排序。每个问题给出可重复的复现步骤、预期行为、实际行为与影响面。

---

## P1【严重·回归】注册表扫描线程崩溃，UI 永久卡在"正在扫描"

- **页面**：安全清理 → 注册表清理
- **复现步骤**：
  1. 启动应用，进入「安全清理」页；
  2. 点击「扫描注册表」；
  3. 观察状态栏。
- **预期**：十几秒内完成扫描，列出无效路径/损坏启动项/卸载残留，并启用「一键清理选中」。
- **实际**：状态栏永远停留在「注册表: 正在扫描无效路径...」，结果表为空，「一键清理选中」永远禁用。
- **根因**（离线复现，直接抛出异常）：
  `core/registry_cleaner.py` 的 `_check_vals()` 与 `_startup_entries()` 调用了
  `self._is_broken_command(d)`，但该方法定义在 `RegistryIssue` 类上（@staticmethod），
  `self`（RegistryScanner 实例）没有该属性 → `AttributeError`。
  该异常发生在 `RegistryScanner.run()`（QThread）内且无兜底 try/except，
  线程静默死亡，`finished` 信号永不发出，UI 无从得知。
- **引入方式**：上一轮"无效路径误报"修复时把解析函数放到了 `RegistryIssue` 上，
  调用点未同步；当时的端到端验证只覆盖了 `clean_issue`，未跑 scan 流程，漏检。
- **影响**：注册表扫描/清理功能 100% 不可用（回归）。
- **复现脚本**：
  ```python
  from core.registry_cleaner import RegistryScanner
  RegistryScanner()._invalid_paths()   # AttributeError
  ```

## P2【严重】启动管理页丢失全部 HKCU 启动项

- **页面**：启动管理
- **复现步骤**：
  1. `reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v TestFoo /d "C:\x.exe"`；
  2. 打开应用「启动管理」页（或点刷新）。
- **预期**：列表包含 TestFoo 以及系统里真实存在的 ctfmon/OneDrive/Edge 自启动等 HKCU 项。
- **实际**：HKCU Run 的所有值都不出现；仅显示 HKLM 与 WOW6432Node 的项。
  （本机实测：HKCU Run 有 4 个值，页面 0 个显示。）
- **根因**：`ui/startup_mgr.py::_load` 中
  `reg_root = 0x80000000  # HKEY_CURRENT_USER` —— **0x80000000 实为 HKEY_CLASSES_ROOT**，
  HKCU 应为 0x80000001。`OpenKey(0x80000000, "...\\Run")` 打开的是 HKCR 下不存在的键，
  抛 OSError 被静默吞掉。
- **影响**：用户自己的自启动项不可见、不可禁用；页面信息严重不完整（长期存在的历史 bug）。

## P3【中】启动文件夹中的 desktop.ini 被当作启动项

- **页面**：启动管理
- **复现步骤**：打开「启动管理」页，查看「启动文件夹/公共启动」行。
- **预期**：只列出 .lnk/.url 等真实启动项。
- **实际**：本机出现 2 行 `desktop.ini`（用户与公共启动目录各一）。
- **根因**：`_load()` 对启动文件夹 `os.listdir` 后未过滤系统文件。
- **影响**：列表噪声；用户可能误禁用/删除系统文件（删除路径现走回收站，风险可控但仍属错误）。

## P4【低】大文件页类别显示英文 "System"

- **页面**：大文件
- **复现步骤**：扫描任意含 `.bin`/`.dll` 等文件的磁盘，查看类别列。
- **实际**：显示英文 `System`（本机夹具 DCBigFixture.bin 显示 "System"）。
- **根因**：`ui/large_files.py` 的 `CAT_NAMES` 缺少 `System` 等 helpers 返回类别的中文映射
  （`get_file_extension_category` 可返回 System/Font/Mobile App/Web/Net/Shortcut/Program）。
- **影响**：中英文混排，观感不一致。

## P5【低】安全等级标签显示英文

- **页面**：文件可视化（安全列）、安全清理（安全等级列）
- **复现步骤**：扫描后查看「安全」列。
- **实际**：显示 `Safe / Clean / Caution / Protected`。
- **根因**：`utils/constants.py` 的 `SAFETY_LABELS` 文案为英文，未随全中文 UI 本地化。
- **影响**：界面语言不一致。

## P6【中】磁盘分析器（TreeMap 可视化）整页不可达

- **复现步骤**：启动应用，遍历侧边栏 10 个导航项。
- **预期**：能进入磁盘分析器（`ui/disk_analyzer.py`，含 squarify TreeMap + 文件列表 + 删除）。
- **实际**：`main.py` 的 `NAV_ITEMS`/`PAGE_CLASSES` 均无 `disk_analyzer`，页面类从未被构造；
  `TreemapWidget` 亦随之成为死代码。
- **影响**：一个完整功能（含此前所有修复）对用户不可见。

## P7【中】QThread.run 普遍缺少异常兜底

- **复现步骤**：见 P1。任何工作线程内的未捕获异常都会导致线程静默死亡、
  UI 停留在"进行中"状态且无任何提示。
- **根因**：`RegistryScanner.run()`（及其它 QThread 子类）无 try/except 包裹。
- **影响**：任何引擎层异常都表现为"永远转圈"，难以定位（P1 正是因此才在 GUI 上表现成卡住）。

## P8【信息】进程管理刷新约 15 秒且无进度反馈

- **复现步骤**：进程管理 → 刷新进程列表。
- **实际**：277 进程约 15s 后才出结果，期间只有"正在读取进程列表..."。
- **根因**：`_ProcessWorker.run` 对全部进程做两次 `cpu_percent` 采样（含 0.5s sleep）+ `as_dict`。
- **影响**：体感慢，但可接受；记录备查。

## P9【信息·前轮遗留】安全清理「一键清理」在 UI 线程同步执行

- **复现步骤**：分析完成后点「一键清理」；清理期间拖动窗口。
- **实际**：UI 冻结直至清理完成（本数量级通常 1~3 秒，Edge 缓存大时更久）。
- **影响**：体验问题；本轮未修，纳入本轮修复（见 03 文档 F8）。

## P10【信息·工具限制】AX 自动化无法切换 QTreeWidget 行的复选框/选中态

- **复现步骤**：对任意树行执行 AXPress / AXToggle / AXSelect 后点对应按钮。
- **实际**：应用弹出"请先选择…"防呆提示。
- **影响**：仅影响自动化测试驱动方式（已用离屏 harness 覆盖），真实鼠标操作不受影响。
  防呆提示本身验证正确。

## P11【信息】一次性窗口异常（不修复）

- 会话中出现一次窗口最小化与状态栏文本串扰，重启后无法复现，无日志证据，
  判定为自动化观测干扰，非应用缺陷。

## P12【中·F1 修复后新暴露】`@dll,-index` MUI 间接字符串被误报为无效路径

- **页面**：安全清理 → 扫描注册表
- **复现步骤**：修复 P1 后点击「扫描注册表」，查看结果列表。
- **实际**：24 个问题中约 20 条为 `Invalid path: oregres.dll,-203`、`imageres.dll,-4` 之类，
  对应注册表值形如 `@%SystemRoot%\system32\oregres.dll,-203`（FriendlyAppName 等）。
- **根因**：`@` 开头的值是 Windows MUI 间接字符串（指向 DLL 中的资源文本），
  不是文件路径；`_is_broken_command` 未跳过，把含 `\` 的整串当路径做 exists 判定 → 误报。
- **影响**：用户全选清理会删除 FriendlyAppName/ApplicationIcon 等正常值，
  破坏"打开方式"列表的友好名称显示。P1 修复后扫描从不可用变为可用，此误报才得以暴露。
